# Security and captured data

Browser tools execute page JavaScript. Only inspect authorized targets, preferably local development or staging, with synthetic data. Known trackers and private-network targets (literal or DNS-resolved) are blocked by default and connections are pinned to the validated address, but WebRTC/UDP traffic, arbitrary site telemetry, application side effects, Shadow DOM coverage, and authenticated sessions require separate consideration. These browser request guards are not an OS network firewall or a sandbox for untrusted sites.

Literal IP classification uses CIDR ranges. Mapped/compatible IPv6, IPv4-translated addresses, well-known NAT64 (`64:ff9b::/96`), and 6to4 inherit the embedded IPv4 classification. Metadata (including AWS's IPv6 address), link-local, unspecified, multicast, broadcast, documentation/reserved ranges, and Teredo stay blocked even with `--allow-private`. Private IPv4, carrier-grade NAT, protocol-assignment/benchmark IPv4, IPv6 ULA, and deprecated site-local ranges require that explicit flag. Native loopback remains available for development.

Local-use NAT64 (`64:ff9b:1::/48`) is always denied: its deployment-specific embedding lengths cannot be inferred safely from the literal alone. Hostnames are resolved when first encountered (successful results cached per browser context; failed or timed-out lookups are retried) and every returned address goes through the same classification, so a public-looking name that resolves to metadata or a private range is blocked. Connections are pinned: every inspection context sends `route.fetch()` and browser sockets through a local proxy (`scripts/_pinning.mjs`) that resolves the name once at connection time, applies the same policy to every answer, and connects to that validated address. Chromium does not resolve the name itself when a proxy is configured, so a short-TTL rebinding answer cannot redirect the connection; TLS stays end to end with the original hostname for SNI and certificate checks. Chromium's own background traffic goes through the same policy. A failed or timed-out lookup blocks by default. `--allow-unresolved-dns` explicitly permits continuing without address validation for trusted proxy environments: names that fail locally are then connected by hostname, without pinning. Limits: Chromium bypasses proxies for loopback (allowed by policy anyway), WebRTC/UDP traffic does not use the HTTP proxy, and network translation beyond the documented ranges is not inferred. The tools are not a sandbox for untrusted URLs.

Other native IPv6 literals must belong to global unicast `2000::/3`, after reserved exclusions, or to an explicitly handled local range. Unrecognized allocations are denied. Legitimate future allocations require a reviewed policy update rather than silently expanding access.

HTTP responses are fetched with automatic redirects disabled. Chromium never receives their redirect headers: each approved GET main-navigation hop is restarted explicitly (at most 20 hops, within the navigation timeout). Redirects for subresources, non-GET navigation, and unsupported destinations are aborted and recorded in `blockedRedirects`. Use canonical asset URLs when redirected images/styles/API resources are missing. Script-driven redirects outside initial preparation can be interrupted; report partial coverage rather than treating the result as a faithful render.

This mediation buffers HTTP responses in Playwright and changes transport/timing conditions; it does not impose a hard response-download size limit. It can change caching, browser address-space checks, and rendering behavior. Local-network permission is restored only for visited loopback main origins, never globally or for public origins, to preserve normal local development WebSockets. The IP policy still applies to literal and resolved addresses; pinning the resolved address remains outside its guarantees.

WebSockets are routed explicitly through the same target/tracker checks. `--block-writes` also rejects all WebSocket connections and records `WEBSOCKET` in `blockedWriteMethods`, along with non-GET/HEAD HTTP methods. First-party telemetry using otherwise permitted requests remains possible. POST-based reads, CORS preflights, and real-time UI may stop working with this option, and GET requests can still have side effects. Service workers are disabled in inspection contexts to keep requests under the inspection path; offline/cached experiences may render differently.

Keep `.audit/` outside version control. Masked fields do not hide names or messages elsewhere on a page. Review reports, PNGs, console messages, and copied assets before sharing. Do not commit environment files, authentication state, tokens, customer information, or licensed reference assets. The inventory does not read response bodies by default. Optional copies require known, unencoded responses up to 5 MB each, with a 60-image/50 MB buffering budget; local file copies share that budget. These limits do not impose a hard cap on Chromium's network downloads.

Report vulnerabilities through GitHub's private vulnerability reporting if enabled. Do not publish secrets or captured customer data in a public issue. A public report should contain only a synthetic reproduction and a description of impact. If data has already been exposed, remove access and rotate affected credentials through the relevant provider; a redaction patch does not invalidate an exposed credential or remove Git history.

Only the author's public name and authorized email should be added as personal attribution. Do not append agent session IDs, local machine identifiers, account details, or unnecessary coauthor metadata.

Text redaction is best effort. It covers common authorization/cookie headers, Bearer/Basic values, JWT shapes, known filesystem path forms, emails, and Brazilian ID/phone formats; it may redact legitimate text and miss other personal data. It does not inspect pixels or hide arbitrary names/messages in screenshots. Synthetic data and manual review of all artifacts remain necessary. Static image reports omit the project-root path and replace file and directory names with per-scan identifiers.

Static image inventories replace file and directory names with per-scan identifiers; no reverse map is saved unless explicitly requested with `--source-map`. An optional map contains real relative paths and is written only to a new Git-ignored file in the project, outside the report output; do not share it. `extract-styles --axe-details` follows the same rule for axe selectors, which can reveal internal page structure. Reports, screenshots, and rendered content can still contain sensitive data. Text redaction is best effort and must be reviewed before sharing.
